# dsh-loop-watcher —— 打转的**通知器 + 计数器 + 交接器**

**[English README → README_EN.md](README_EN.md)**

> 本插件提供两类能力，它们服务同一条工作流 —— **打转之后，紧接着就是交接**：
>
> | 能力 | 出现在哪里 |
> |---|---|
> | 横幅通知、会话头「已打断 N 次」计数徽章 | 输入框上方、会话标题行 |
> | 一键交接（开新会话并带上旧会话的接手材料） | 会话「...」菜单 |

---

## 〇、与上游守卫的关系（先读这一节）

本插件**不做思考链的检测与切断**，那部分由独立的上游项目完成：

| 项目 | 协议 | 说明 |
|---|---|---|
| [`@mrweicodes/dsh-loop-guard`](https://github.com/MrWeiCodes/dsh-loop-guard) | MIT | 版权 © 2026 argszero, MrWeiCodes and contributors |

- 它挂在 host 侧 `llm/stream` 上，能从流内部切断退化的模型调用；切断一次就
  注入一条 `source.kind === 'loop-guard'` 的消息，**本插件只读那条消息**。
- **本插件是它的补位插件**：不装上游 = 横幅与计数永远不出现（没有数据来源）。
  交接功能、设置页、前缀注入**不依赖上游**，装不装都能用。

> ⚠️ **不装上游 = 横幅与计数永远不出现**（没有数据来源）。
> 建议先装上游再装本插件：
>
> ```powershell
> dsh plugin --profile <profile> add @mrweicodes/dsh-loop-guard
> dsh plugin --profile <profile> add <本插件路径>
> ```

## 一、这是什么、不是什么

**它不做检测、不做切断。**

> 当前行为：点「交接对话」后走**隐藏注入**（输入框上方显示蓝色胶囊
> 「已经进入交接对话」，发送时把交接指令拼在你的内容前面），你的输入以
> **`用户追加：`** 段头单独成段，与指令分明不糊在一起。

上游每切断一次，就注入一条 `source.kind === 'loop-guard'` 的消息；本插件**只读**那条消息。

## 二、你会看到什么

### ① 横幅通知（输入框上方）

上游切断时，默认一声不响。本插件把它变成一条横幅，带三个按钮：

```
⚠ 检测到一次思考循环，已被上游守卫打断                        ×
你的思考内容已连续重复 531 个字符而没有进展，因此响应被中途截断。
        [定位到循环处] [关闭提醒] [生成交接指令*]
```

`*` 生成交接指令按钮**只在配置了导出工具时出现**（见第四节）。

### ② 计数徽章（会话标题行右侧）

紧跟在「N 个后台任务」右边：

```
◉ 本对话未被打断        ← 0 次（中性态，绿点）
◉ 本对话已打断 2 次      ← 1–2 次（黄色描边）
◉ 本对话已打断 4 次      ← ≥3 次（红色描边）
```

- **0 次也显示**：让你分得清「现在是健康的」与「插件没生效」
- **数字只增不减**：按会话记，翻历史不会倒退
- **点一下就定位**：滚到最近一次打断发生的位置并闪一下
- 上限：每会话 400 条记录、最多 30 个会话（防无界增长）

### ③ 一键交接（会话「...」菜单）

菜单里多一行「交接对话」：自动新建会话，输入框上方出现蓝色胶囊**「已经进入交接对话」**，
你直接输入自己的提示词，**发送时插件把交接指令（含前缀）自动拼在你的内容前面**——
指令全文从头到尾不进输入框，一格都不占。

胶囊会在第一次发送后自动消失。刷新页面后胶囊靠 localStorage 恢复，注入照常生效。

**发送内容的段落结构**（两段分明，不糊在一起）：

1. **第一段** = `交接对话：` 段头 + 交接指令全文（前缀 + 素材获取段 + 方法论段）；
2. **第二段** = `用户追加：` 段头 + 你写的内容 —— 你在输入框里写了什么就原样成段，
   新会话一眼能分清「哪些是上下文、哪些是你现在的新要求」。

有图片/文件附件时，附件照常放在文字段之后、相对顺序不变；纯附件或空白草稿时
不会留下空的「用户追加：」段头。

### 新会话的标题：`交接对话：<旧会话标题>`

接手后侧栏里多出来的那个会话，标题会自动变成「**交接对话：+ 你交接的那个会话的标题**」。

标题由两条路配合得出：

| 路径 | 做什么 | 失败会怎样 |
|---|---|---|
| **主路径：注入段头** | 第一段以 `交接对话：` 开头。DSH 的标题 fallback 取「第一条人类消息的开头词」，于是标题自动变成 `交接对话：<你写的话>` | 不会失败 —— 只是文字本身 |
| **精修：`session.rename()`** | 交接成功后把标题改成 `交接对话：<旧会话标题>`。而且 rename 会写入 `source.kind: 'user'`，DSH **随即停止自动生成标题**，fallback 那个略糙的标题不会被后续覆盖 | 静默失败，标题保持 fallback 版（已经能看） |

> **为什么不是「沿用旧标题 + 数字后缀」**（`xxx 2`）：数字看不出你接手的是哪个任务，
> 而旧标题本身就是那个任务的浓缩描述。改名前它长这样 ——
> `【交接模式】你现在接手的是`，因为指令被拼在内容最前面，标题生成器读到的全是交接指令。

接手指令（隐藏注入的那段）由三部分组成：

1. **前缀提示词**（设置页可开关、可改，见第四节）—— 让新会话直接进入接手状态；
2. **素材获取段**：配置了导出工具时带一条导出命令；没配置时改为「自己根据工作目录、产物与记忆库线索找上文」；
3. **方法论段**：抓重点的五项清单 + 工作方式要求。

> 设置页里的「前缀提示词」= **整段会被隐藏注入的文字**（上面三部分里除「上一个会话…」
> 标识行以外的全部 + 前缀本体），不只是开头几行。

## 三、安装

```powershell
# 1) 先装上游守卫（检测+切断）
dsh plugin --profile <profile> add @mrweicodes/dsh-loop-guard

# 2) 再装本插件（clone 下来的仓库根目录，那里就是插件本体）
dsh plugin --profile <profile> add <仓库根目录>
```

两个插件的 entry id 分别是 `loop-guard`（上游）与 `loop-watcher`（本插件），不撞车。

> **为什么是从本地目录装，而不是 `add dsh-loop-watcher`**：仓库里的
> `package.json` 带 `"private": true`，这是有意的 —— 本插件目前只以源码形式
> 分发，没有发布到 npm。把仓库 clone 下来、`add <仓库根目录>` 即可；
> 若想以后发布到 npm，删掉那一行 `private` 再 `npm publish`。

## 四、配置：设置页（交接前缀 + 导出工具路径）

打开**侧边栏 → 设置 →「打转守望」**，四张分组卡片（都是即时保存，改完即生效）：

| 卡片 | 设置项 | 存哪里 | 说明 |
|---|---|---|---|
| **横幅提醒** | 横幅上显示「生成交接指令」 | localStorage + 内存 | 关掉后横幅只保留「停止 / 关闭提醒」，交接改用会话「...」菜单 |
| **计数徽章** | 变红的打断次数 | localStorage + 内存 | 默认 3。1 = 一被打断就红；填非法值自动退回 3 |
| **交接对话** | 前缀提示词（开关 + 正文） | localStorage + 内存 | 开 = 交接指令最前面注入这段前缀；清空正文 = 不注入 |
| **旧会话导出工具** | 导出工具路径 | localStorage | 可选。配置后指令带导出命令；留空则指令不含命令，交接仍可用 |

> 前缀的**默认值**是内置的一段「接手状态提示词」（`lib/client.js` 里的 `PREFILL_TEXT_DEFAULT`）。
> 没动过设置 = 一直用它；在设置页清空 = 明确不要前缀。

> **「旧会话导出工具」不是遗留设置**：本插件刻意不自带导出工具。装了上游守卫的话，
> 它包里有个现成脚本 `node_modules/@mrweicodes/dsh-loop-guard/tools/analyze-session.mjs`
> （设置页里也显示了这条候选路径），可以直接填；任何「吃一个会话短 ID、吐出可读文本」的脚本都行。
> ⚠️ 上游那个脚本输出的是**打转分析报告**而非完整交接素材，所以插件只提示、不自动填。

### 不用设置页的两种旧方式（仍然有效）

**方式 1**：页面控制台（F12）执行一次，改完刷新页面生效：

```js
localStorage.setItem('dsh-loop-watcher:export-tool', 'D:\\你的目录\\导出会话.cmd')
localStorage.setItem('dsh-loop-watcher:prefill-enabled', '0')  // 关闭前缀注入
localStorage.setItem('dsh-loop-watcher:prefill-text', '自定义前缀……')
```

**方式 2**：直接改 `lib/client.js` 里的常量 `EXPORT_TOOL_DEFAULT` / `PREFILL_TEXT_DEFAULT`。

> 本仓库**不含**导出工具本体（它是另一个独立工具，依赖 Python 3.14+ 的
> `compression.zstd`）。你可以用任何能读 DSH 会话记录的方式 —— 上游守卫的
> `tools/analyze-session.mjs` 就是一个现成的 Node 方案。

## 五、没有导出工具时，交接还能用吗？怎么用？（新用户先读这节）

**能用，而且这是默认状态** —— 本插件不自带导出工具，新装上就是「未配置」，
交接菜单照常出现、照常工作。

### 两种状态的实际差别

| | 配置了导出工具 | 未配置（默认） |
|---|---|---|
| 交接指令里 | 带一条「导出旧会话」的 PowerShell 命令 | 改为「自己根据工作目录、产物与记忆库线索找上文」这一段 |
| 新会话拿到上文的方式 | 跑命令 → 读素材文件 | 自己翻目录、读文件、查记忆库线索 |
| 横幅上的「生成交接指令」按钮 | 出现 | 不出现（它的语义就是生成带导出命令的指令） |

**没有导出工具，新会话依然能接手**，只是要从零摸索上文，效率略低。

### 未配置时，建议这样提高接手质量

### 1. 在项目目录里交接

新会话的工作目录如果是原项目，它能直接看到产物文件、代码与已有的说明文档 —— 这是最强的"上文"。

### 2. 给新会话**指明该挖什么**（本节是重点，建议读完）

新会话最怕的不是"没有材料"，而是**不知道该看哪儿**。一份好的接手材料应该覆盖下面五类事实 ——
你也可以主动在输入框里补一句，把这几项点出来：

| 素材里该有什么 | 为什么关键 | 没有它的后果 |
|---|---|---|
| ① **任务目标**（以你自己的原话为准） | 唯一不会被误读的依据 | 新会话只能猜你要什么 |
| ② **已做到哪一步 / 产物在哪** | 判断从哪里接着干 | 重复劳动，或推倒重来 |
| ③ **关键文件与路径** | 省掉大范围翻找 | 在无关文件上浪费时间 |
| ④ **踩过的坑与已验证的结论** | 那些结论常是反直觉的、且代价很高才换来 | **重复踩同一个坑** |
| ⑤ **还剩什么没做（含不确定项）** | 不确定项恰恰最需要你确认 | 自作主张地替你做决定 |

> ④ 是最容易被忽略、代价最高的一项 —— 看起来"不合理"的写法，往往正是上次踩坑换来的。
> 本仓库的 `验证/` 目录就是一个例子：那里每条断言都对应一个真实失败过的问题。
> 交接时告诉新会话"看看那边的注释"，比让它从零试错快得多。
>
> 另外提醒一句：**历史记录里标注"打转/降智"的部分结论不可信**，只能当作"试过什么"的线索，
> 需要新会话自己判断哪些站得住。

### 3. 交接时在输入框里多写一句背景

插件胶囊只代表"指令已就绪"，**你自己的话才是最有价值的补充**。例如：

> 接手：上次在做 DSH 插件的交接前缀功能，已完成隐藏注入，剩余 README 与打包上传。
> 关键文件在 `lib/client.js`，先从第 2100 行看起。

### 4. 记忆库 / 常驻笔记

如果你的工作流里有 `AGENTS.md`、项目交接文档之类的常驻说明，新会话会读它们 ——
把"当前进度与下一步"写进去，比任何导出都管用。

## 五之二、用上游守卫的 `analyze-session.mjs` 当导出工具（零 Python 依赖）

不想装 Python 3.14，也能拿到一条"命令行直通车" —— 前提是你已经装了上游守卫
（它是个纯 Node 包，随 npm 一起装进来）。包里自带一个能读 DSH 会话记录的脚本：

```
node_modules/@mrweicodes/dsh-loop-guard/tools/analyze-session.mjs
```

它直接吃 DSH 的会话文件（`.jsonl` 与 `.v4.jsonl.zstd` 都认，按内容自动判别格式），
不需要额外的 zstd 命令行工具。它的本职是**打转分析** —— 把真实会话记录重放到守卫的
检测器上，回答"这次到底会不会被切、切在第几段"，而不是整理接手素材。

实测（一个 1605 次模型调用的大型会话）输出形态：

```text
steps:   1605 model call(s)
  #   turn/step   reasonChars  textChars  chunks  verdict   fired  repeatedRun  cycleSpan ...
```

JSON 模式（`--json`）每个 step 带的是 `verdict / fired / repeatedRun / cycleSpan /
repeatedChars / wouldBreak` 这类判定字段。

### 怎么用

先找出你要交接的那个会话文件。会话文件在 DSH 的数据目录下：

```powershell
# Windows：会话文件按「工作目录编码\<sessionId>\session.v4.jsonl.zstd」存放
Get-ChildItem "$env:USERPROFILE\.dsh\sessions" -Recurse -Filter 'session.v4.jsonl.zstd' |
  Sort-Object LastWriteTime | Select-Object -Last 10 FullName, LastWriteTime
```

拿到路径后先试跑一次（确认它能读）：

```powershell
$node = 'node'   # 或你机器上的 node 绝对路径
$script = 'node_modules\@mrweicodes\dsh-loop-guard\tools\analyze-session.mjs'
$session = '<上一步查出来的 .zstd 文件路径>'

& $node $script $session --json | Out-File '.\打转报告.json' -Encoding utf8
```

### ⚠️ 它与"理想导出工具"的差别（重要，先读再接）

上游脚本的本职是**打转分析**（把会话重放到检测器上、判断会不会被切），不是接手素材。
所以它的输出里**没有**下面这三样新会话最需要的东西：

| | 上游 `analyze-session.mjs` | 专门做接手素材的工具 |
|---|---|---|
| 打转统计 / 命中位置 | ✅ 很详细（上表那些字段） | 一般没有 |
| 涉及的文件清单 | ❌ | ✅ |
| 执行过的命令 | ❌ | ✅ |
| 最后的对话（接手最关键） | ❌ | ✅ |
| 依赖 | 只需要 Node | 本例需要 Python 3.14 |

**结论**：用它，你得到的是"这个会话打转得怎么样"，不是"这个会话干到了哪一步"。
所以更实用的用法是**反过来** —— 让新会话**自己跑它**来读上文：交接时在输入框里补一句
"先跑一下上游守卫的 analyze-session.mjs 看这个会话的记录"，比让插件自动生成一条跑得通
但内容不对路的命令更有用。

> 想要完整效果，思路是：会话记录在 `.dsh\sessions` 下，已经是 JSONL（可选 zstd 压缩），
> 自己挑出 `user/message` 与 `assistant/message` 两类事件拼成 Markdown 就是接手素材。
> DSH 侧没有"反压缩"命令行工具，但 Node 与 Python 都有现成的 zstd 解压支持。

## 六、localStorage 键一览（想重置就删掉）

| 键 | 存什么 |
|---|---|
| `dsh-loop-guard:count` | 各会话累计打断次数（seq 集合，**只增不减**） |
| `dsh-loop-guard:alert` | 各会话当前待处理的横幅 |
| `dsh-loop-guard:dismissed` | 各会话最后关掉的通知 seq |
| `dsh-loop-guard:self-test` | 演练开关（`guard`/`count`/`1`） |
| `dsh-loop-guard:log` | 自带检测的命中日志（默认关闭时才用） |
| `dsh-loop-guard:mode` | 自带检测的「自动中断」开关（默认关闭时才用） |
| `dsh-loop-watcher:export-tool` | **导出工具路径**（本插件新增） |
| `dsh-loop-watcher:prefill-enabled` | **交接前缀开关**（'1'/'0'；未写 = 开） |
| `dsh-loop-watcher:prefill-text` | **交接前缀正文**（未写 = 内置默认；写了空白 = 明确不注入） |
| `dsh-loop-watcher:pending-handover` | **待注入的交接指令**（最近一条；发送时自动清掉） |
| `dsh-loop-watcher:count-severe` | **徽章变红的打断次数**（正整数，默认 3；非法值自动退回 3） |
| `dsh-loop-watcher:banner-draft` | **横幅上是否显示「生成交接指令」**（'1'/'0'；未写 = 显示） |

> 为什么有一半的键名是 `dsh-loop-guard:*` 而不是插件名：**刻意保留旧键名**。
> 改成新名字会让已经累计的计数被静默清零 —— 数据不丢比命名整齐重要。
> 唯一新增的键是 `dsh-loop-watcher:export-tool`。

## 八、已知限制（如实说明）

1. **上游没装 = 横幅与计数什么都不显示**（除非打开 `OWN_DETECTION`）。
2. **上游改版可能换掉 `source.kind`** → 本插件静默失效（不报错）。
3. **计数只算「看得见的」**：会话文件里有多少次打断它读不到；历史没被分页加载出来的也暂不算（滚动加载后会补上，且只增不减）。
4. **「定位」是 DOM 级实现**：靠聊天区渲染时写死的 `data-chat-*` 属性找行。
5. **未配置导出工具时**：交接菜单照常可用（指令不含导出命令），但横幅上的「生成交接指令」按钮不出现（按钮语义就是生成带导出命令的指令）。
6. **插槽名若被 DSH 改掉**，对应 UI 静默消失（不报错）。
7. **两条交接路径已统一**：横幅上的「生成交接指令」与会话菜单里的「交接对话」现在走
   同一条链路（`runHandover`）。旧版横幅会各拼一套「写交接文档」的提示词，那个行为已删除；
   源码里仍留着 `buildGuardDraftPrompt` 这个旧函数但**没有任何调用点**，回归有一条断言
   专门盯它不许复活。
8. **标题精修依赖会话绑定**：`session.rename()` 在会话还没激活、连接未就绪时会失败。
   失败是静默的 —— 注入段头已经让标题 fallback 给出 `交接对话：<你的原话>`，
   精修只是把它换成 `交接对话：<旧会话标题>`。极端情况下标题保持 fallback 版，能看。
9. **设置页入口**：设置面板打开的是上次停留的分区；本插件没有「编程打开设置页」的宿主 API（外壳不开放该状态），所以从侧边栏「设置」进入。
10. **交接注入依赖会话绑定**：胶囊挂载时若该会话的 `session` 还没就绪会重试（2.4 秒窗口）；极端情况下注入器没挂上，指令不会发出（输入框是干净的，不会发出半截指令）。
11. 改 `lib/client.js` 后**刷新页面**生效；若个别改动不生效再重启 DSH。
12. **`验证/` 的两个 `.cmd` 不能并发跑**：每段开跑前都会从 `client.js` 重新抽出
    `验证/校准/core-from-client.mjs`，两个进程同时写同一文件会互相覆盖。一次跑一个。
13. **`验证/` 依赖 Node 22+**：脚本按 `PATH` → 常见安装位置 → DSH 自带运行时
    （`~/.dsh/dsh-runtimes/*/dependencies/node/bin/`）的顺序找 node。三者都没有时
    才会提示「找不到 Node.js」并退出 1。

## 九、验证

本仓库带五段回归（`验证/verify.ps1`），全部通过。

> **断言条数由脚本自己打印，不要在这里写死一个数字。** 跑完最后会输出：
>
> ```
> 第 2 段：N 条断言
> 第 3 段：N 条断言
> 第 4 段：N 条断言
> 第 5 段：N 条断言
> 合计：N 条断言
> ```
>
> 这个数**随语料有无而变**：
> - 语料齐备时：第 3 段 114 + 第 4 段 74 + 第 5 段 104 = **292**；
> - 公开仓库（无语料，第 2 段跳过）：第 3 段降到 107 → **285**，
>   少的 7 条正是依赖真实语料的那几条。
>
> 为什么不在 README 写死：五段不共用计数器，第 3/4 段只打印「全部通过」不报条数，
> 只有第 5 段会打印「通过 N 项」。旧版 README 曾把第 5 段这个 104 当成五段总数，
> 少算了整个第 3、4 段 —— 所以现在改成让脚本自己汇总，文档只描述怎么看。

| 段 | 验什么 |
|---|---|
| 1 | 从 `client.js` 抽出检测核心（保证「验证的就是真在跑的那份代码」） |
| 2 | 打转判据回归（对真实会话数据，含正负样本） |
| 3 | 运行期逻辑（snapshot 提取 / 整条链路 / 交接指令 / 打断计数 / 配置门控） |
| 4 | 计数徽章运行时（真实执行 client.js + 替身 React 渲染组件） |
| 5 | 交接功能（框架 / 菜单项 / 接手指令文案 / 前缀三态 / **注入器端到端**：首次发送合并、防重入、销登记 / **标题段头与 rename 精修**：成功、抛错静默、拿不到服务也不抛 / 胶囊契约 / 设置页注册 / 配置门控） |

跑法：`powershell -File 验证\verify.ps1`（或双击 `验证\跑验证.cmd`，跑全部五段）。

只想单独跑第 5 段（交接功能）时用 `验证\跑验证-handover.cmd`。

> 这两个 `.cmd` 的内容刻意保持**纯 ASCII**：`.cmd` 是按控制台代码页解码的，
> 里面写中文（哪怕只是中文文件名）会变成乱码再传给 Node。所以它们用通配符
> `for %%f in (*-handover.mjs)` 去定位脚本，而不是写死那个中文文件名。

> **别同时双击两个入口**：每一段开跑前都会从 `client.js` 重新抽出
> `验证/校准/core-from-client.mjs`，两个进程同时写同一个文件会互相覆盖
> （抽出来的是同一个内容，但写坏的窗口期会让对方读到半截文件）。
> 一次跑一个即可。

> **关于第 2 段（判据回归）在公开仓库里会跳过**：它要对照 `验证/校准/*.jsonl`
> 里的真实会话语料，而那些语料含推理全文、内网 IP、本机路径等私人信息，
> 发布时已被 `.gitignore` 排除 —— 所以 clone 下来的仓库天生没有它们。
> 缺语料时套件**不会崩**，而是明确打印「本段跳过，这是刻意的隐私决定」后继续跑
> 其余四段（退出码仍为 0）。想在本机跑完整第 2 段，自备同形状语料
> （每行 `{turn, step, text}`）并同步更新 `校准/python-baseline.json` 即可。

## 十、文件结构

**仓库根目录就是插件本体** —— clone 下来直接 `dsh plugin add <仓库根>` 即可。

```
.                          ← 仓库根 = 插件本体（有 package.json）
├─ package.json          ← name / entry id / dsh.client.inject（三个 UI 包的并集）
├─ cordis.patch.yml      ← 一个 entry: loop-watcher
├─ lib/index.js          ← Host 半：空壳（全部行为在 Client 半）
├─ lib/client.js         ← 全部功能（约 3100 行，按 #region 分段）
├─ locale/{zh,en}.json   ← 插件列表页的标题与描述
├─ LICENSE               ← 本插件 MIT + 上游 MIT 版权声明
├─ README.md             ← 本文
├─ README_EN.md          ← English README
├─ .gitignore            ← 挡掉真实语料与开发留档
└─ 验证/                 ← 回归套件（不参与插件运行，可整目录删掉）
   ├─ verify.ps1         ← 总入口，依次跑 5 段
   ├─ 跑验证.cmd / 跑验证-handover.cmd
   ├─ verify-{detect,runtime,badge}.mjs / 验证-handover.mjs / extract-core.mjs
   └─ 校准/              ← 对照基准与通知形状样本（已脱敏）
```
